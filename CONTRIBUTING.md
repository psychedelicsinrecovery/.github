`psychedelicsinrecovery` organization that doesn't have its own `CONTRIBUTING.md`.

## Before you contribute

PIR® is a recovery-community nonprofit first and a technical project second. If a repository here
touches anything related to member privacy, meeting content, or personal recovery stories, treat that
content with the same confidentiality standards PIR®'s in-person and virtual meetings hold to —
anonymity and privacy come before any technical convenience.

## How to contribute

1. Open an issue describing what you'd like to change or add before submitting a large pull request
   — for a small fix (typo, broken link), a PR alone is fine.
2. Fork the repository and create a branch for your change.
3. Keep commits focused and describe *why* a change was made, not just what changed. Start each commit subject with
   one gitmoji and a type, `:memo: docs(scope): subject` or `:bug: fix(scope): subject`; the twelve the family uses,
   and why the `:alias:` form, are in [GITMOJI.md](https://github.com/drasticstatic/my-template/blob/main/GITMOJI.md).
   It is a warn-only hint, never a gate.
4. Open a pull request against `main` (or `preview`, where a repository has one) and reference the issue it addresses,
   if any. A helper may open the pull request; a person with the role merges it, with a merge commit, never a squash,
   so every author's attribution survives (SOP-OPS-002 in PIR®'s procedures).

## Reporting problems

For anything security-related, see [`SECURITY.md`](./SECURITY.md) instead of opening a public issue.
For anything else — bugs, broken links, content corrections — a regular GitHub issue is the right
place.

## Questions

This organization's GitHub presence is new. If something about this process is unclear or doesn't
fit a particular repository, open an issue and ask — this guide will get more specific as the org's
codebase grows.
